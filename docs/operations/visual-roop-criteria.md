# Visual Roop Criteria

この基準は、演劇同好会サイトの見た目改善をroopで回すための採点表である。目的は「雰囲気がよい」ではなく、公演発見、予約、稽古記録閲覧、団体理解が速くなること。

## 参照した外部パターン

- Sydney Opera House: `What’s on` を主導線にし、Highlightsでジャンル、日付、画像を並べて比較しやすくしている。
  - https://www.sydneyoperahouse.com/
- The Public Theater: hero直下に大きいシーズン導線と `Coming Up` を置き、今日/直近の公演へすぐ進める。
  - https://publictheater.org/
- Chaptr theatre website guide: theatre siteは `What’s On`、production page、ticketing journey、mobile/accessibility、ongoing updatesが中核。
  - https://chaptr.studio/how-to-design-a-theatre-website-that-takes-center-stage/
- Plank best theatre websites: 強い背景映像/写真、余白、清潔なナビゲーションで劇場の印象と機能を両立させる。
  - https://plank.co/en/blog/10-best-theatre-websites-in-2024/
- NN/g card definition: カードは情報をまとめ、詳細へ進む短い入口として機能する。画像、タイトル、要約、日時、CTAのまとまりが重要。
  - https://www.nngroup.com/articles/cards-component/

## 現サイトの改善候補

### 1. Hero

現状:

- 写真は入ったが、演劇同好会固有の「人が舞台を作っている感じ」はまだ弱い。
- コピーと背景写真の関係が抽象寄り。

改善:

- 人の顔が写る舞台写真を使ってよい。顔が主役になりすぎる写真より、稽古・照明・演出中の身体が見える写真を優先する。
- heroは「団体の空気」を一発で伝える。公演情報とは別に、活動感を出す。
- H1は短く、下のCTAは `公演を見る` と `稽古記録を読む` の2本まで。

合格基準:

- 1440px幅の初期表示で、写真、団体名/見出し、CTAがすべて読める。
- 写真が暗すぎない。顔や身体の輪郭が判別できる。
- 文字が写真に埋もれない。

### 2. 公演情報

現状:

- `潜る男` とA4チラシの枠は機能している。
- ただし「最新公演が主役」「他公演は比較用」という階層がまだ弱くなり得る。

改善:

- 最新公演はA4チラシを大きく固定。右側にタイトル、日程、会場、予約CTA。
- 小さい公演カードは日付、状態、会場を圧縮し、チラシ比率は必ずA4。
- `予約ページへ` は最も強いCTA。`PRページを見る` は副CTA。

合格基準:

- `.show-flyer` の実測比率が `0.7071 ± 0.01`。
- 最新公演の予約CTAが初期表示または1スクロール以内にある。
- 公演一覧とPR詳細で、同じ公演情報が矛盾しない。

### 3. 稽古記録・ブログ

現状:

- note風に寄せる余地がある。
- pickup UIは情報の重心が曖昧になりやすい。

改善:

- 記事カードは「著者/日付」「タイトル」「短い抜粋」「いいね」を1単位にする。
- pickupは大きいカード1件 + 小さいリスト2件にする。ランキング感を出しすぎず、編集部推薦に見せる。
- カード全体をクリック領域にし、いいねだけは独立操作にする。

合格基準:

- 1カードの情報は5秒で理解できる。
- タイトルが2行を超えてもレイアウトが崩れない。
- いいねボタンは押下/取り消し状態が視覚的に分かる。

### 4. 団体紹介

現状:

- 写真配置は改善したが、まだ「写真を置いた」感が残る可能性がある。

改善:

- 写真は2枚まで。片方は舞台/照明、片方は人の活動が見える写真。
- 数字カードは写真に重ねるのではなく、情報帯として扱う。
- 「何をしている団体か」「後輩が何を更新すればよいか」を短く分ける。

合格基準:

- 写真同士の主従が明確。
- メトリクスが写真の邪魔をしない。
- モバイルで写真と数字が縦に自然に積まれる。

### 5. CSS品質

改善:

- 色は単色テーマに寄せすぎない。黒/白/赤/紙色だけでなく、照明色や舞台の影をアクセントにする。
- セクションごとに余白リズムを揃える。
- カードの角丸は8px以下を基本にする。
- hoverは派手に動かさず、影、明度、下線、矢印移動で差を出す。
- 画像は `object-position` を個別に調整する。

合格基準:

- 375px、768px、1440pxで横スクロールがない。
- ボタン内テキストが折り返しで崩れない。
- 画像読み込み失敗がない。
- カラーが1系統に沈まない。

## Visual Roop Score

各roopで下の10項目を0/1/2点で採点する。合計16点以上で採用、12-15点は再調整、11点以下は戻す。

| 項目 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Heroの第一印象 | 汎用的 | 写真は良いが弱い | 団体の空気が伝わる |
| 公演導線 | 迷う | 分かるが弱い | 予約/PRへすぐ進める |
| A4チラシ | 崩れる | だいたい合う | 実測で合う |
| ブログらしさ | DB感が強い | 記事カードに見える | note的に読める |
| pickup | 意味不明 | 見えるが弱い | 推薦意図が分かる |
| 写真運用 | 飾り | 雰囲気は出る | 活動の実在感が出る |
| CSS完成度 | 粗い | 整っている | 余白/影/色/hoverが一貫 |
| モバイル | 崩れる | 読める | 快適 |
| アクセシビリティ | 不明 | 最低限 | CTA/alt/コントラスト良好 |
| CMS整合性 | ローカル/本番差あり | fallbackで補完 | API/fallback/PRが一致 |

## 次のVisual Roopでやる順序

1. 現ページのスクリーンショットを 1440px / 768px / 375px で取る。
2. Hero、団体紹介、公演、稽古記録をこの基準で採点する。
3. 1roopにつき改善対象は1セクションだけに絞る。
4. 人の写真を使う場合はHeroまたは団体紹介のどちらか一方から始める。
5. 実装後、Chromeで比率、横スクロール、画像読み込み、CTA導線を検査する。
6. このrepoからObsidianへ開発ログを直接記録しない。外部devlog automationの対象であることは妨げない。
